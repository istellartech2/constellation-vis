# AI Agent Guide

These notes collect the essentials an autonomous coding assistant needs before touching this project. Share them across tools (Copilot Workspace, GPTs, Cursor, etc.) so they all behave consistently.

## Project At A Glance
- React 19 + TypeScript + Vite front end that renders Earth, orbits, and analysis views in Three.js.
- Orbital mechanics backed by `satellite.js` with custom math in `src/lib/astronomy.ts`, `visibility.ts`, `perturbation.ts`, and helpers in `src/lib/utils.ts`.
- UI split between `src/components/ui` (editor/options controls) and `src/components/analysis` (coverage, maintenance, solar impact dashboards).
- Data for satellites, constellations, and ground stations lives in TOML under `public/` and is converted at build time into `src/lib/satellites.generated.ts` (do not edit this file manually).

## Tooling & Commands
- Install once per clone with `bun install` (requires Bun ≥1.3.11 and Node ≥16).
- `bun run dev` launches Vite with a `predev` hook that regenerates satellite data.
- `bun run build` runs TypeScript project references and Vite bundling; use it for smoke testing before PRs.
- `bun run lint` (ESLint 9) and `bun run test` (Bun native test runner) are the guardrails; both should pass after code changes.
- Regenerate data manually with `bun scripts/generate-satellites.ts` whenever TOML in `public/` changes.
- **Note:** Tests use Bun's native test runner (not Vitest). Test files import `describe`, `it`, `expect` from `bun:test` (see `tests/celestrak-import.test.ts` for mock patterns).

## Repository Map
- `src/lib/` ─ domain logic (ephemeris math, formatters, configuration, generated data stub).
- `src/components/` ─ React components:
  - `analysis/` analysis panels and chart helpers.
  - `ui/` shared controls, dialogs, and headless Radix UI wrappers.
  - `useSatelliteScene.ts` integrates Three.js scene state with React.
- `public/` ─ user-editable TOML describing satellites/constellations/ground stations plus static assets.
- `scripts/` ─ build-time Bun scripts (currently `generate-satellites.ts`).
- `tests/` ─ Bun test specs plus Python helpers for reference data generation.
- `docs/` ─ deeper explanations (`docs/perturbation.md` covers drag and harmonics modeling).
- `docs/constelation-cli-SKILLS.md` ─ tracked source for the copy-ready CLI agent guide distributed as `dist/SKILLS.md`.

## Implementation Guidelines
- Stay inside the existing stack: React function components, hooks, and Three.js helpers. Reach for `clsx`/`tailwind-merge` rather than bespoke string building.
- Styling uses Tailwind CSS v4 with configuration embedded in `src/index.css`. Prefer utility classes or the predefined component classes (`.analysis-button`, `.side-panel`, etc.) over ad‑hoc CSS.
- Heavy computation should live in `src/lib` utilities; keep React components declarative and effectful logic inside hooks (`useSatelliteScene`, custom hooks under `src/lib` if needed).
- Generated file `src/lib/satellites.generated.ts` is owned by the Bun script. Modify TOML inputs instead of editing it by hand, and document any schema changes in the script.
- Favor pure/typed utilities; extend existing types in `src/lib/satellites.ts`, `config.ts`, or dedicated type modules when introducing new data.
- When adding APIs or async flows, centralize fetch logic (see `tests/celestrak-*` for current patterns) and respect bun’s native `fetch`.

## Testing & Quality
- Default to `bun run test` for unit coverage; focus on creating deterministic fixtures using the JSON/Python helpers already present.
- Test files use Bun's native test runner: import `{ describe, it, expect, mock, afterEach }` from `bun:test`.
- For mocking fetch or global state, use `bun:test`'s `mock()` function. See `tests/celestrak-import.test.ts` for patterns.
- Use `bun run lint` to catch TypeScript/React/Tailwind issues early.
- For changes affecting orbit propagation or visibility, add/adjust cases in `tests/orbitalCoordinates.test.ts` or compose new specs alongside existing ones.
- Run `bun run build` before shipping major UI or configuration edits to ensure the generated satellites file and bundler still succeed.

## Data & Configuration Workflow
- `public/satellites.toml`, `constellation.toml`, and `groundstations.toml` define the domain data. Constellation shells are expanded in `scripts/generate-satellites.ts` using SGP4-compatible orbital elements.
- If you introduce new TOML schema fields, update both the Bun generator and any corresponding TypeScript types or formatters.
- The generator normalizes metadata (NORAD IDs, object names). Keep new fields consistent with the serialization logic (`serialize()` helper) and the resulting `SatelliteSpec` type.
- Re-run the generator (or rely on `predev`/`prebuild`) after TOML edits so `satellites.generated.ts` stays in sync; review the diff before committing.

## Gotchas
- Never commit edits inside `dist/` or `node_modules/`.
- The visualization depends on Three.js side effects; ensure any new GL resources are disposed in `useSatelliteScene` cleanup paths.
- Watch for UTC vs local time handling: epochs are stored as ISO strings and parsed into `Date` objects in the generator.
- Large data imports can block the main thread; batch updates or move heavy math into worker-friendly utilities if you expand functionality.

Armed with this playbook, an AI agent should be able to explore confidently, make changes safely, and respect the domain-specific workflows in this repository.

# 計算の概要

**衛星の位置と速度は、`satellite.js` の SGP4/SDP4 で計算します。** TLE を読み込む場合も、軌道要素を入力する場合も、コンステレーションを生成する場合も、この位置計算を使います。

```text
軌道を入力・生成 → SGP4/SDP4 で位置計算 → 表示・アクセス・通信経路・日照を評価
```

## 時刻・地球・座標の基準

- **時刻**：計算は UTC を基準にします。軌道データのエポック（基準時刻）と解析開始時刻は別です。古い TLE を基準時刻から離れて使うほど、実際の軌道とのずれが大きくなり得ます。
- **地球**：地上局の緯度・経度・高度と詳細な被覆判定には WGS-84 楕円体を使います。赤道半径は約 6378 km、極半径は約 6357 km です。設計の簡易被覆計算、衛星間リンクの地球遮蔽、食の判定には球近似を使います。
- **座標**：SGP4 が返す衛星位置は地球の自転に固定されない座標系（TEME）です。地球の回転角（GMST）を使って地球固定系へ変換し、地上局との位置関係を求めます。極運動や UT1−UTC の補正は含みません。
- **単位**：軌道の距離・高度は km、速度は km/s、入力する角度は度が基本です。寿命・推進剤・電力の式で使う単位は、各詳細資料に記載しています。

厳密な定数と高度の定義は [座標・時刻](analysis-implementation.md#coordinates)・[軌道伝播](analysis-implementation.md#propagation) を参照してください。

## 各機能で計算すること

| 機能 | 計算方法と結果の意味 | 詳細 |
| --- | --- | --- |
| 3D 表示 | 指定時刻の衛星位置と地上軌跡を表示する | [軌道伝播・座標系](analysis-implementation.md#propagation) |
| アクセス | 地上局から見上げる角度（仰角）や衛星の視野条件で可視性を判定し、見える時間の割合や中断時間を集計する | [可視性・可用性](analysis-implementation.md#visibility) |
| 全球アクセス | 選んだ 1 本の経線上で、緯度ごとのアクセスを評価する | [評価範囲](analysis-implementation.md#global-access) |
| 地上リンク・デューティ | 衛星と端末の接触時間、距離、伝搬遅延、ドップラーを求める。デューティは解析期間に占める接触時間の割合 | [CLI](constelation-cli-SKILLS.md)・[計算式](analysis-implementation.md#link-duty) |
| ISL（衛星間リンク） | 距離と地球遮蔽などから接続できるリンクを作り、設定した重みの合計が最小の通信経路を探す | [経路探索](isl-routing.md) |
| コンステレーション設計 | 衛星数・軌道面・配置を決める。ミッション設計では簡単なモデルで候補を絞り、SGP4 で詳しく評価する | [配置方式](constellation-patterns.md)・[ミッション設計](constellation-design.md) |
| RGT（回帰軌道） | 同じ地上軌跡を繰り返すための高度・傾斜角の候補を近似式で求める。SGP4 に渡す軌道を決める設計計算 | [条件式](RGTorbit.md) |
| 軌道寿命・推進剤 | 別の大気抵抗モデルで長期の高度低下を見積もり、軌道維持に必要な速度変更量と推進剤量を求める | [摂動モデル](perturbation.md)・[維持解析](analysis-implementation.md#maintenance) |
| 電力 | 衛星位置から日照・食を判定し、発電と消費の差からバッテリ残量を計算する | [日照・電力](analysis-implementation.md#solar-power) |

## 結果を読むときの前提

アクセスやリンク成立は**幾何的な接触機会**です。電波性能、通信容量、運用スケジュールは含みません。ISL の総遅延には、距離から求めた伝搬遅延に設定したペナルティも加わります。

可用率や被覆は、一定間隔の地点・時刻サンプルで評価します。100% という結果も、全地点・連続時間の保証ではありません。RGT・寿命・電力の見積りには、それぞれ近似モデルを使います。

数式・単位・既定値・実装箇所とモデルの限界は [解析モデルと実装](analysis-implementation.md) を参照してください。

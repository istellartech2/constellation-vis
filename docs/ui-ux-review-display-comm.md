# UI/UX レビュー：「表示」「通信」タブ

> **状態: 対応済み（記録として保管）。** 指摘と改善案は #26・#29 で実装した（クイックトグル HUD のみ見送り）。結果は [§6 実装状況](#6-実装状況2026-10-30) を参照。本文のファイル名・行番号はレビュー時点のもので、`IslTab.tsx` はその後 `CommTab.tsx` と `IslSection.tsx` に分かれている。

対象: `src/components/ui/OptionTab.tsx`（表示）、`src/components/ui/IslTab.tsx`（通信）、関連する `SatelliteEditor.tsx` / `LayerList.tsx` / `visualization.ts`。
確認方法: コード読解 + 開発サーバーでデスクトップ (1400×900) とモバイル (375×812, ボトムシート) を目視。

---

## 1. 結論（ごちゃついて見える理由）

「項目が多い」こと自体より、**整理の軸がない**ことが原因です。

1. **1 つのタブに性質の違うものが混在している。** 表示タブには「見た目だけ（国境線）」「解析結果を変えるパラメータ（衛星の視野半角）」「操作（ビュー保存・KML 読込）」「アプリ設定（画面テーマ）」が同じ見た目で並んでいる。触ってよいものか、数値に影響するのかがラベルから分からない。
2. **同じ概念が複数のタブに散っている。** 「地上局から衛星が見えるか」という 1 つの概念が 4 か所にある（下表）。
3. **画面に見えているものと計算が食い違っている。** 地上局コーンが示す範囲と、衛星が緑（可視）に変わる条件が別の値で動いている。ユーザーが「コーンに入っているのに赤い」を見ても理由が分からない。

| 概念: 地上局↔衛星の可視 | 置き場所 |
|---|---|
| 地上局コーン表示・最小仰角・距離上限 | 通信タブ |
| 可視/不可の衛星色（リンク可視・リンク不可） | 表示タブ › 衛星ポイントカラー（折りたたみ） |
| レイヤーの色分け「地上局から可視」 | シナリオタブ › 表示レイヤー |
| 局ごとの最低仰角（実際の判定値） | シナリオタブ › 地上局エディタ（TOML） |

## 2. 現状の棚卸し

凡例: 🎨 見た目だけ / 📐 解析・判定に影響 / ⚙️ 操作・保存・アプリ設定

### 表示タブ（上から順）
- ビュー保存 ⚙️ — 現在のビューを保存、保存済みチップ
- 地球の見た目 🎨 — テクスチャ、国境線、雲、経緯線、地球を明るく、背景を白
- 衛星の見た目 — サイズ 🎨、影で暗く 🎨、太陽光きらめき 🎨、**選択衛星の摂動 (J₂/J₃)** 📐
- 座標系・補助表示 — ECI/ECEF/GSE 🎨、太陽方向と黄道面 🎨、GEO 🎨
- 衛星の視野（センサ定義）（折りたたみ）— コーン表示 🎨、**視野半角・Along/Cross-track** 📐（地上局アクセス解析が使用）
- 衛星ポイントカラー（折りたたみ）— リンク可視/不可/選択中 🎨（意味は通信）
- KML 重ね合わせ（折りたたみ）⚙️
- 画面テーマ ⚙️

### 通信タブ
- 地上局の通信範囲 — コーン表示 🎨、最小仰角・距離上限（**見た目専用だが判定値と別物**）
- 衛星間経路探索 (ISL) — 有効トグル、地点 A/B、入替
  - 結果 — KPI 3 枚、内訳、切替回数、タイムライン解析ボタン
  - 経路の重み付け（折りたたみ）— 中継ペナルティ、切替えにくさ、先読み回避、種別ペナルティ GSL/ISL 📐
  - 詳細設定（折りたたみ）— 参加衛星、最大距離、遮蔽マージン、シェル別リンク方式、経路色 🎨
  - 診断（折りたたみ）— 候補エッジ数、計算時間、**再計算間隔** 📐（設定なのに診断に入っている）

## 3. 問題点（根拠つき）

### A. 正しさに関わるもの（最優先）

**A1. 最低仰角が 4 系統あり、表示と判定が一致しない**
- 衛星の緑/赤、ISL の地上局リンク、地上局アクセス解析 → 局ごとの `gs.minElevationDeg`（`visualization.ts:1674`, `isl/types.ts:26`。サンプルでは 40° と 25°）
- 地上局コーンの形 → 通信タブのグローバル値（既定 30°、`visualization.ts:637`）
- ISL の臨時地点 → 10°（`isl/types.ts:182`）
- 全球アクセス解析 → 解析モーダル内のローカル値（既定 30°、`GlobalAccessAnalysis.tsx:35`）

通信タブの「地上局の通信判定は最低仰角のみを使います」（`IslTab.tsx:241`）は、どの最低仰角かを書いていない。

**A2. コーンの長さとリンク最大距離も別物**
コーン距離上限の既定は 1,000 km（`App.tsx:103`）、ISL/GSL の最大リンク距離は 5,000 km（`isl/types.ts:173`）。コーンは「通信できる範囲」と名乗っているが、どちらの判定とも一致しない。

**A3. 解析に効くパラメータが「表示」に隠れている**
視野半角・傾きは地上局アクセス解析の条件にもなる（説明文 `OptionTab.tsx:453`）が、表示タブの折りたたみ内にあり、コーン非表示時は既定で閉じている（`defaultOpen={showSatelliteFovCones}`, `:452`）。解析結果が変わった理由を探しに行く場所として「表示」は想像しにくい。

**A4. 地点 A・B を「地上局」にすると両方とも先頭の局になる**
`EndpointRow` はモード切替時に `groundStations[0]` を入れる（`IslTab.tsx:599`）。A・B 両方で選ぶと「Tokyo ⇄ Tokyo」になり、結果は「経路なし（到達不能）」と表示される（実機で確認）。原因が「同じ地点」であることが伝わらない。

### B. 構造（ごちゃつきの主因）

- **B1. 表示/通信の境界があいまい。** 地上局コーン（見た目）は通信、可視/不可の色（通信の概念）は表示、視野（解析条件）は表示。
- **B2. 性質の違う操作が同じ見た目。** ビュー保存・KML・テーマが見た目設定と同列のセクション。画面テーマはタブの最下部で見つけにくい。
- **B3. 1 つのチェックが 2 つの状態を変える。** 「太陽方向と黄道面を表示」は `showEcliptic` と `showSunDirection` を同時に切り替え、片方だけ ON の状態はチェック OFF に見える（`OptionTab.tsx:432-440`）。
- **B4. ISL の設定階層が深い。** 背景色つきグループ → 結果 + 折りたたみ 3 つ → その中に SubHeader → シェル別カード。中継ペナルティ・切替えにくさ・先読み回避は意味が近いのに独立スライダーで、ⓘ を読まないと何を動かせば何が変わるか分からない。
- **B5. 設定と診断の混在。** 再計算間隔（設定）が「診断」に入っている。

### C. 部品・文言

- 衛星表示サイズのセレクトが「点 Npx」と「S/M/L/LL」という別単位を 1 つに混ぜている。
- 「リンク可視/リンク不可」は何とのリンクか不明（実際は「いずれかの地上局から見える」）。
- 日本語 UI に英語ラベル「Along-track / Cross-track」が混在。
- 地点 A/B のモード選択が 84px のセレクトで、局名セレクトと二段構え。
- 「選択衛星の摂動 (J₂/J₃) を表示」は見た目設定ではなく解析的な表示で、衛星選択時にしか意味がない。

### D. モバイル（ボトムシート）

ハーフ表示では 2 セクション程度しか見えず、よく使う ON/OFF（経緯線・国境・コーン等）までスクロールが必要。トグルを触るたびにシートが地球を半分隠す。

## 4. 改善案

整理の原則を 1 つ決めて全体に当てはめる。

> **「表示」= 触っても数値が変わらないもの。「通信」= 誰と誰がつながるかの条件と、その条件の可視化。**
> 条件の可視化（コーン・可視色）は、その条件の隣に置く。

判定テスト: ヘルプを読まずに「どのタブにあるか」「数値結果に影響するか」が分かること。

### P0 — 小さく単独で出せる（正しさ・混乱の除去）

1. **コーンを局ごとの最低仰角に追従させる。** グローバルスライダーは既定で非表示にし、「全局を一時的に上書き」として残すか削除。コーン長の既定を GSL 最大距離に合わせる（または「最大リンク距離に合わせる」を既定 ON に）。→ A1, A2
2. **地点 B の既定を A と別の局にする。** A=B のときは「経路なし」ではなく「A と B が同じ地点です」と表示。→ A4
3. **文言の修正。** 「リンク可視/不可」→「地上局から見える/見えない」。「地上局の通信判定は最低仰角のみ…」→「各地上局の最低仰角（地上局エディタで設定）で判定します」。Along/Cross-track → 「進行方向の傾き / 横方向の傾き」。
4. **太陽方向と黄道面を 2 つのチェックに分ける**（または 1 状態に統合）。→ B3
5. **再計算間隔を詳細設定へ移動**し、診断は結果カード下の 1 行（`候補エッジ 1,234 · 計算 3.2 ms`）に縮める。→ B5
6. **画面テーマをパネルヘッダーのアイコンへ移動。** → B2

### P1 — 情報設計の再編（本命）

#### 表示タブ（見た目だけ）
```
表示
├ クイック表示（アイコントグルのグリッド、1 画面に収める）
│   経緯線 / 国境 / 雲 / GEO / 太陽方向 / 黄道面 / 衛星コーン / 地上局コーン
├ 地球         テクスチャ、明るさ、背景色
├ 衛星         サイズ（「画面上で一定 / ズームで拡大」を切替 + サイズ）、影で暗く、きらめき
├ 座標系       ECI / ECEF / GSE（説明 1 行）
└ 重ね合わせ   KML
```
- ビュー保存は 3D 画面上（再生バー横のブックマークボタン）へ移動。表示設定というより「操作」のため。
- 摂動 (J₂/J₃) は衛星選択時の情報カード（`SatelliteInfo`）側のトグルへ移動。

#### 通信タブ（つながる条件 + 経路）
```
通信
├ 地上局リンク
│   局ごとの最低仰角（一覧表示、編集は地上局エディタへのリンク）
│   □ 可視範囲コーンを表示   □ 衛星を可視/不可で色分け（色チップ）
│   □ 表示レイヤーも可視で色分け（現シナリオタブの色分けを移設）
├ 衛星センサ視野  ※ 解析に使用
│   視野半角 / 進行方向の傾き / 横方向の傾き   □ 3D にコーンを表示
└ 衛星間経路 (ISL)  [有効トグル]
    地点 A ⇄ 地点 B（局名を直接選ぶコンボ。末尾に「座標を指定…」）
    結果（KPI + 1 行の内訳 + タイムライン解析）
    経路の方針  [最短遅延 | バランス | 安定重視 | カスタム]
       └ カスタム時のみ 4 スライダーを表示
    詳細  参加衛星 / リンク距離 / シェル別方式 / 経路色 / 再計算間隔
```
- 「解析に使用」バッジを 📐 系のセクションに付け、表示タブには 1 つも置かない。
- 経路の重み付けはプリセット化し、通常は 1 クリックで選べるようにする（スライダーは「カスタム」時のみ）。

#### 却下した代替案
- **対象別（地球 / 衛星 / 地上局 / 座標系）で見た目と条件を同居させる案。** 対象から探しやすい反面、見た目の設定と解析条件が再び同じセクションに混ざり、「触ると数値が変わるか」の区別がつかない状態が残るため、今回の課題（ごちゃつき）を解消しにくい。

### P2 — 後続

- **3D 画面上のクイックトグル。** `IslHud` と同じパターンで、右上に経緯線・コーン・ISL 経路など 4〜5 個のアイコンを常設。モバイルではシートを開かずに切り替えられる。→ D
- **`DisplaySettings` を 1 つのオブジェクト + reducer で受け渡す。** 現在は約 45 個の props が App → SatelliteEditor → OptionTab と個別に渡っている（`SatelliteEditor.tsx:624-671`）。P1 の移設コストを下げる前提作業。UX 改善そのものではないが、P1 の前にやると安全。

## 6. 実装状況（2026-10-30）

P0・P1・P2 の props 整理を実装した。3D 画面上のクイックトグルは不要と判断し作っていない。

- **表示設定の受け渡し**: App の約 30 個の `useState` を `DisplayOptions` 1 つにまとめ、`display` / `onDisplayChange(patch)` で渡す（`src/lib/viewState.ts` の `displayOptionsFromSaved` / `mergeDisplayOptions` / `toDisplaySettings`）。保存形式 `DisplaySettings` は互換のまま。
- **コーン = 判定値**: 地上局コーンは各局の `minElevationDeg` で開く。グローバルの最小仰角スライダーと `groundConeMinElevationDeg` は廃止（AI 連携 API では受け付けて無視）。距離上限は「コーンの長さ（見た目のみ）」に改名。
- **通信タブ**（`CommTab.tsx`）: 地上局リンク（局ごとの最低仰角一覧・見える/見えない色・レイヤー色分け・コーン）／衛星センサ視野／衛星間経路。判定・解析に効く 2 セクションに「解析に使用」バッジ。
- **ISL**（`IslSection.tsx`）: 地点 A/B を 1 つのセレクト（地上局 or 座標を指定…）に統合。A=B は「同じ地点です」と表示（HUD も）。重み付けは「最短遅延／バランス／安定重視／カスタム」のプリセット（`src/lib/isl/costPresets.ts`）、スライダーはカスタム時のみ。診断セクションは結果下の 1 行に縮め、再計算間隔は詳細設定へ。
- **表示タブ**: 保存したビュー／地球／重ねて表示（2 列グリッド。太陽方向と黄道面は別々のチェック）／衛星（大きさの決め方と大きさを分離、選択中の色）／座標系／KML。
- **移設**: 画面テーマ → パネルヘッダーのアイコン。摂動 J₂/J₃ → 衛星情報カード内の開閉セクション。ビュー保存は 3D 画面ではなく表示タブ先頭に残した（タブのプリセットとして）。

# 衛星の姿勢（エディタ衛星）

エディタの衛星（SGP4 で伝搬する衛星）の向きを、運用でよく使う 5 つの姿勢則から選べます。
姿勢は **全エディタ衛星に共通の 1 つの設定** で、3D の視野コーン・機体モデル、地上局アクセス設計、
日照・電力（発電係数を「姿勢から計算」にしたとき）が同じ値を使います。表示レイヤー（GPU J2 の大規模表示）には姿勢がありません。

実装: `src/lib/attitude/types.ts`（型と既定値）、`src/lib/attitude/satelliteAttitude.ts`（純関数）、
`src/lib/attitude/settings.ts`（保存値の検証と UI ラベル）。テスト: `tests/satellite-attitude.test.ts`、`tests/fov-golden.test.ts`。

## 機体座標

| 軸 | 意味 |
| --- | --- |
| +Z | センサの視線側（地球指向では真下 = nadir） |
| +X | 進行方向側（ram） |
| +Y | Z × X（地球指向では −軌道法線） |

太陽電池パネルの翼は ±Y 方向に伸び、パネル面の法線は

- **固定（−Z面）**: 機体 −Z（地球指向では天頂）。
- **1軸追尾（Y軸まわり）**: −Z を機体 +Y まわりに `driveAngleRad` だけ回したもの（右ねじ。0 で −Z、+π/2 で −X）。

姿勢はクォータニオン `q`（機体 → ECI。ECI は satellite.js と同じ TEME）で表します。

### 読み込んだ3Dモデルを機体座標に合わせる

近接カメラの機体モデルは 表示タブ › **3Dモデル** の「近接カメラで使う衛星モデル」で選べます（既定は標準バス。
`DisplayOptions.satelliteModel` = `"satellite-bus"` または `"library:<id>"`）。「モデルを読み込む…」で glTF（.glb、
データ埋め込みの .gltf）を読み込み、プレビューの軸（+X 進行方向・+Y・+Z 地球方向（センサ））を見ながら合わせます。

1. **元データの上方向**（Y-up（glTF標準）/ Z-up（CAD））を選ぶと向きを自動推定する（地球側 = 下、
   水平の長い辺 = 翼（±Y））。プレビュー左下の「モデル X/Y/Z」を見ながら、**進行方向（+X）になる軸** と
   **地球側・センサ方向（+Z）になる軸** をモデル自身の ±X/±Y/±Z から選んで直す（直交する 2 軸。+Y = Z × X は自動）。
   CAD（Z-up）由来なら地球側は多くの場合「モデル −Z」。ロケット（原点が底面）のときは「機首（+X）」「腹側（+Z）」と表示。
2. **大きさ**: 単位（m / cm / mm / インチ）か実寸（最大長 m）。検出サイズと、換算後の機体 X/Y/Z の大きさが表示されます。
3. **原点**: 衛星は「中心」。近接カメラはモデルの原点を衛星位置に置き、視野コーンの頂点・軌道線もそこを通ります。
4. **太陽電池パドル**（任意）: 1軸追尾で回す部品をノード一覧から選ぶ（プレビューで黄色の枠、「回転を確認」で 0–180° 回して確かめられる）。選んだ部品は自分の中心線を通る機体 Y 軸に平行な軸で回り、
   モデルのままの向き（セル面が −Z を向いている状態）が 0° です。

近接カメラ中は衛星カードに「機体モデル: 標準バス · 変更…」が出て、表示タブの 3Dモデル（ライブラリが空なら読み込みダイアログ）を開けます。
モデルはこのブラウザにだけ保存されます（保存ビューや AI 連携にはモデル ID だけが入り、モデルがないブラウザでは標準バスで表示）。
詳細は [trajectory-layer.md](trajectory-layer.md#model-library-srclibmodellibrary)。

## モード

| キー | 表示名 | +Z | +X の決め方 |
| --- | --- | --- | --- |
| `lvlh` | 地球指向（LVLH） | nadir | 速度の水平成分（`W × R̂`, `W = unit(R̂ × V̂)`）。従来の FOV と同じ |
| `yawSteering` | 地球指向＋ヨー制御 | nadir | 太陽方向を水平面へ射影した向きの ± のうち、+X 側（ヨー 0 に近い方） |
| `station` | 地上局指向 | 局が自分の最低仰角以上の間は衛星 → 局。それ以外は地球指向 | 速度の水平成分にできるだけ近く |
| `sun` | 太陽指向 | 反太陽方向（パネル面 −Z が太陽を向く） | 速度の水平成分にできるだけ近く |
| `inertial` | 慣性指向 | 赤経・赤緯の方向（ECI 固定） | 天の北極の射影 |

どのモードも「+Z を決め、+X は候補ベクトルの +Z に垂直な成分」で作ります。候補が +Z とほぼ平行（|sin| ≤ 1e-9）なら次の候補へ進み、
最後は ECI +Z → ECI +X を使うので、常に正しい回転が得られます。

### タイブレーク（テストで固定）

- **ヨー制御の 2 解**: パネル軸 Y を太陽に直交させる +X は ±2 通り。LVLH の +X との内積が 0 以上の方（ヨー角が小さい方）を選ぶ。
  そのため太陽の水平成分が進行方向と直交するとき（1 周に 2 回）に 180° 反転する。最大レートがなければ瞬時、あれば機体 +Z まわりに回る（下の「運用スケジュール」）。
- **ヨー制御の特異点**: 太陽が ±Z（真上・真下）にあるときはヨーが決まらないので、ヨー 0（地球指向と同じ）。
- **太陽指向のロール**: 速度の水平成分が太陽方向と平行なときは、+Y = −軌道法線（地球指向と同じ向き）でロールを決める。速度がなければ天の北極 → ECI +X。
- **慣性指向の極**: 赤緯 ±90° では天の北極が使えないので ECI +X を基準にする。
- **地上局指向の切替**: 指定局の `minElevationDeg`（その局自身の値）を境に切り替える（最大レートがなければ瞬時）。判定は `d·u ≥ sin(minEl)·|d|`
  （u は測地上方向、`accessGrid.ts` と同じ形）。局の ECEF → ECI は `satellite.gstime(date)` による Z 軸回転で、`visibility.ts` と同じ。
  指定局がシナリオにない（削除・改名）ときは実効モードを地球指向にし、UI に「選んだ地上局が見つからないため地球指向で計算しています」と表示する。
- **速度なし**: 地球指向で速度が使えない場合、従来関数（`computeFovBoresightEcf` など）は取付角を無視した純 nadir に戻る。これは変更していない。

## 運用スケジュール（時間によるモード切替と旋回レート）

`SatelliteAttitudeSettings` の任意フィールド。どれも未設定なら従来の単一モードと完全に同じ（`prepareAttitudeContext` の `schedule` が null になり、
従来のコード経路をそのまま通る。`tests/fov-golden.test.ts` と `tests/attitude-schedule.test.ts` で固定）。

| フィールド | UI | 意味 |
| --- | --- | --- |
| `trackStationDuringPass` | 地上局が見えている間は地上局指向にする | `stationName` の局が自分の最低仰角以上の間は地上局指向。局が見つからなければ無視 |
| `eclipseMode` | 日陰の間の姿勢（基本と同じ／各モード） | 衛星が地球の影にある間のモード。基本と同じ実効モードなら無視 |
| `maxSlewRateDegS` | 姿勢変更の最大レート（°/s、空欄 = 即時、0〜90） | 切替時にこの角速度で前の姿勢から新しい姿勢へ回る |

**優先順位**: 地上局通過中 > 日陰 > 基本の姿勢（`mode`）。基本が地上局指向なら従来どおり「見えている間は局、それ以外は地球指向」（日陰モードも設定した場合、通過中を日陰より優先させるには通過中のチェックを併用する）。
日陰の判定はアプリ共通の `isInEarthShadow` と同じ（`earthShadowFraction ≥ 0.5`、太陽中心が地球の縁に隠れた時点）なので、衛星カードの「日陰」と一致する。
地上局と慣性指向の赤経・赤緯は基本モードと共通（局の選択は地上局指向と共有）。

**切替の検出**: 実際に効いている法則を離散状態（地球指向／局指向（局が見えている）／太陽指向／慣性指向／ヨー制御 ±）として扱い、
その変化を「切替」とする。基本の地上局指向が局を捕捉・離脱するときや、ヨー制御の 180° 反転も切替に含む。

**旋回（`maxSlewRateDegS > 0`）**: 時刻 t の姿勢は時刻だけの純関数（スクラブしても同じ t なら同じ姿勢）。

1. 過去の状態を衛星ごとの `AttitudeStateProvider`（`attitudeStateProviderFromSatrec(rec)`）で求め、時刻 t から 180°/レート 秒さかのぼる範囲を
   **絶対時刻の 10 秒格子**（エポックからの 10 s の倍数）で走査し、現在と異なる状態の最新の格子点 g を見つける。
2. 区間 [g, g+10 s]（端点固定。問い合わせ時刻 t に依存しない）を二分して切替時刻 t_s を 0.1 s まで求める。
3. 所要時間 T = ∠(q_prev(t_s), q_new(t_s)) / レート。t − t_s < T の間は `q = slerp(q_prev(t), q_new(t), (t − t_s)/T)`（短い方の経路、w ≥ 0 に正規化）。
   ヨー制御の反転（2 解はちょうど 180° 離れ、slerp の経路が決まらない）は `q_prev(t)` を機体 +Z まわりに π·(t − t_s)/T 回す（nadir を保ったまま回る）。

制限: 10 秒より短い区間の切替は見落とすことがある。旋回途中の再切替はつながず、前の法則の姿勢から回り始める（角速度の連続性は保証しない）。
`AttitudeStateProvider` を渡さない呼び出しでは切替は即時。

**計算コスト**（開発機 macOS / Apple Silicon、`bun`、1 衛星 1 時刻、文脈を毎回作成。目安）: 単一モード 1.3 µs、日陰切替のみ（即時）2.1 µs、
旋回 1°/s で約 20 µs（走査 18 点＋二分 7 点 ≈ 25 回の SGP4）、0.1°/s で約 100 µs（走査 180 点）。SGP4 1 回は約 0.5 µs。
同じ文脈（`prepareAttitudeContext` の戻り値）を共有する衛星どうしは、走査格子点の時刻文脈（太陽・GMST）をキャッシュで共有する。

**3D 表示での扱い**: シーンは解決済みの姿勢設定（全体設定＋シェル／衛星ごとの上書き）が同じ衛星をまとめ、グループごとに 1 フレーム 1 回だけ文脈を作る。
視野コーンの旋回はエディタ衛星が 64 機以下のときだけ適用する（旋回中のコーンは衛星ごとに過去状態を走査し、1 フレームあたり 20〜30 回程度の SGP4 を使うため）。
65 機以上（大量表示モードを含む）ではコーンは即時に切り替える。近接の 3D モデルは常に旋回を適用する。

**衛星カード**: 「姿勢」の値は実際に効いているモードと理由を表示する（`activeAttitudeLabel`）。
例: 「地上局指向（通過中）」「地球指向（日陰）」「切替中 → 太陽指向」。スケジュールがなければ従来どおりモード名だけ。

**旧経路との判定**: 地球指向専用の高速経路（従来関数をそのまま使う）を選ぶ呼び出し側は `settings.mode === "lvlh"` ではなく
`isPlainLvlhAttitude(settings, stations)`（文脈なら `isPlainLvlhContext(ctx)`）で判定する。基本が地球指向でも日陰・通過中に別モードへ切り替わりうるため。

## センサ（取付角）

センサの視線は機体 +Z を「進行方向への取付角 a（+X 側へ、機体 Y まわり）」→「横方向への取付角 c（−Y 側へ、機体 X まわり）」の順に傾けた向き:

```
boresight_body = (sin a, −cos a · sin c, cos a · cos c)
boresight_eci  = q ⊗ boresight_body
```

地球指向では機体軸 = LVLH 軸なので、従来の「along-track / cross-track の傾き」と同じ結果になる（`tests/fov-golden.test.ts` が変更前の出力で固定）。
地球指向の計算は従来の関数をそのまま通すので、地上局アクセスや CLI・比較解析の結果は変わらない。

## 太陽電池パネル入射（`solarArrayIncidence`）

```
s_body = q⁻¹ ⊗ s_eci
固定:     cosIncidence = max(0, −s_body.z),            driveAngleRad = 0
1軸追尾:  cosIncidence = √(s_body.x² + s_body.z²) = √(1 − (Y·s)²)
          driveAngleRad = atan2(−s_body.x, −s_body.z)
```

固定パネル＋地球指向では軌道平均でおおよそ 0.3〜0.5 になり、電力解析の手入力既定 0.78 よりかなり小さい。

## 解析との関係

| 解析 | 姿勢の使い方 |
| --- | --- |
| 地上局アクセス設計 | 「衛星の視野も可視条件に加える」を ON にしたときだけ、視野の向きに姿勢を使う（OFF のときは局の仰角条件のみで、姿勢は効かない）。太陽指向ではセンサ（+Z = 反太陽方向）が地球を向くのは昼側の、太陽直下点付近を見る区間だけなので、アクセスは大きく減る（0 にはならない。テストの例では地球指向の 3 割程度） |
| 日照・電力 | 発電係数が「姿勢から計算」のときだけ、各サンプルのパネル入射を使う |
| コンステレーション設計比較 | 常に地球指向で評価する（比較条件に姿勢は保存しない） |
| 全球アクセス・CLI・リンク幾何・ISL・ミッション設計 | 姿勢を使わない |

時刻だけで決まる部分（太陽方向、地上局 ECEF、GMST）は `prepareAttitudeContext` で 1 回計算し、`satelliteAttitudeFromContext` で衛星ごとに使い回せる。
`accessGrid.ts` は時刻ステップごとにこの文脈を前計算し、全衛星で共有する。

## UI

- 通信タブ › **衛星の姿勢とセンサ**（アンカー `#comm-attitude`）
  1. **姿勢**（解析に使用）: 姿勢モード、1 行説明、モード別の入力（地上局指向 → 局の選択、慣性指向 → 赤経・赤緯）、注意書き。
     地上局がないときは「地上局指向（地上局がありません）」を選べない。
     その下に折りたたみの「運用スケジュール」: 「地上局が見えている間は地上局指向にする」（チェック＋局の選択。地上局指向と共有）、
     「日陰の間の姿勢」（基本と同じ／各モード）、「姿勢変更の最大レート」（°/s、空欄 = 即時）。閉じているときは
     「基本: 太陽指向 · 地上局通過中: 地上局指向 · 日陰: 地球指向 · 最大 1.0°/s」のような 1 行要約を表示し、何か設定済みなら開いた状態で始まる。
     シェル／衛星ごとの上書きがある場合は「n 機はシェル／衛星ごとの姿勢設定を使います」と表示する。直下に「使用する解析: 地上局アクセス設計（"衛星の視野も可視条件に加える"がオンの時）、日照・電力（"姿勢から計算"の時）」。
  2. **センサ**（解析に使用）: 視野半角、進行方向への取付角、横方向への取付角（機体に対する角度。地球指向では従来の傾きと同じ）。
  3. **3D 表示**: 視野コーンの表示と色。視線が地球を向いていない衛星のコーンは灰色で薄く描く。
- 解析 › 日照・電力: 太陽電池パネル（固定／1軸追尾）と発電係数（手入力／姿勢から計算）。
- 地上局アクセス設計: 「衛星の視野も可視条件に加える」（保存ビューに保持）と「条件: 姿勢 地球指向 · 視野半角 30°」の条件行。太陽指向（「この姿勢ではセンサが地球を向く時間が限られるため、地上局アクセスは大きく減ります」）・地上局が見つからないときは注意を表示。チェックがオフで姿勢が地球指向以外のときは「現在の姿勢（…）は使われていません。使うには上のチェックをオンにしてください」。
- 3D: 視線が地球を向いていない衛星は灰色の薄いコーンに加えて、ボアサイト方向の破線（コーンと同じ長さ）を描く。

## 保存

`DisplaySettings` / `DisplayOptions`（`src/lib/viewState.ts`）に保存する。古い保存ビューにはないので既定値で読み込む。

| フィールド | 既定 |
| --- | --- |
| `satelliteAttitude` | `{ mode: "lvlh", inertialRaDeg: 0, inertialDecDeg: 0 }`（`stationName` は局を使うとき。`eclipseMode` / `trackStationDuringPass: true` / `maxSlewRateDegS > 0` は設定したときだけ保存） |
| `solarArrayType` | `"fixed"` |
| `satelliteModel` | `"satellite-bus"`（近接の機体モデル。`"library:<id>"` はこのブラウザのモデルライブラリ） |
| `showBodyAxes` | `false` |
| `showBodySunDirection` | `false` |
| `stationAccessUseSatelliteFov` | `false`（地上局アクセス設計の「衛星の視野も可視条件に加える」。画面を閉じても保持） |

AI 連携 API（`src/lib/remoteDisplay.ts`、[ai-api.md](../public/ai-api.md)）でも同じフィールドを受け付ける。`satelliteAttitude` は丸ごと置き換え。
保存ビューの運用スケジュールのフィールドが壊れているときは、そのフィールドだけ捨てて基本モードは残す。
シナリオの地上局が変わったときは `reconcileAttitudeStation` で整合させる（局を使う設定 ― 地上局指向、日陰の間の地上局指向、
通過中の地上局指向 ― で名前が未設定なら先頭局を選ぶ。局が見つからない名前は警告のために残す。局を使わない設定では見つからない名前を消す）。

## シェル・衛星ごとの姿勢

通信タブの設定は全体設定。コンステレーションのシェル（`[[constellation.shells]]`）と個別衛星・編隊（`[[satellites]]`）は TOML の `attitude_mode` / `attitude_station` / `attitude_ra_deg` / `attitude_dec_deg` / `attitude_eclipse_mode` / `attitude_track_station` / `attitude_slew_deg_s` で上書きできる（エディタの「姿勢」折りたたみ。既定は「全体設定に従う（通信タブ）」）。解決は `resolveSatelliteAttitude(spec, global)`（`src/lib/attitude/resolve.ts`）:

- 上書きなし → 全体設定そのもの（同じオブジェクト）。
- `attitude_mode` あり → 姿勢則を置き換える。日陰の姿勢・通過中の地上局指向は上書きに書いたものだけ（省略 = なし）。局名・赤経赤緯・最大レートは省略すると全体設定の値。
- `attitude_mode` なし → 書いたキーだけ全体設定を上書き（`attitude_track_station = false` で通過中指向を止める等）。

編隊エントリのキーは deputy 全機に適用する（chief からは継承しない）。3D・衛星カード・地上局アクセス（衛星の視野あり）・日照/電力（姿勢から計算）が衛星ごとに解決した姿勢を使い、通信タブには「n 機はシェル／衛星ごとの姿勢設定を使います」と出る。設計比較・全球アクセス・CLI は姿勢を使わない。キー一覧と検証は [constellation-patterns.md](constellation-patterns.md) §10。

## 扱わないもの

# ITU申請データのローカル読み込み

シナリオの「ITU申請からインポート」を開く。ダイアログは「ファイルを開く」と
「ファイルの入手先」（公式申請ページへのリンク）を分けている。申請ページで添付の
**SNS(MDB) As Received Copy** を取得し（ZIPなら展開）、ファイルとして開く。
読み込み後は構成を選ぶ画面に切り替わり、フッターのボタンで「追加」か
「置き換え」かを明示する。同じ申請国・名称の配置がシナリオにあれば置き換え、
なければ追加する。基準日時の初期値はシナリオの開始時刻。
GIMS、EPFDマスク、全体SRSデータベースではなく、1ネットワークのSNS MDBを選ぶ。

元MDBの配布・サーバー転送・プロキシ取得は行わない。ブラウザの専用Workerで
`mdb-reader` により必要な4テーブル（notice, non_geo, orbit, phase）だけを読み、
解析完了・キャンセル・タイムアウト・アンマウント時にWorkerを終了する。
上限は128 MiB、1構成10,000機。超過時はエラーとし、黙って間引かない。

## 構成と注記

orbit_set_idごとに構成を分け、単一構成はdefaultとする。別構成は合計しない。
生MDB内のnotice IDは公開ページのNotice IDと異なる場合があるため、同一視しない。
元期・受領日も同一視しない。

カタログは公式URLと確認した説明だけを持つ。MDB本体・抽出済みの軌道データは
リポジトリに含めない。SHA-256がレビュー済みのファイルと一致したときだけ、
対応する公開申請URL、日付、添付注記の要約を表示する。別版や他の申請は
未レビューとし、添付注記の確認を促す。

カタログは `src/lib/filings/catalog.ts` で、システム（`FILING_SYSTEMS`、例：Starlink）→
シリーズ（例：第1世代、第2世代 3M–3W）→ 申請（`FILING_CATALOG`、1ネットワーク1件）の
3階層で持つ。ダイアログはシステムごとに折りたたみ、検索・国の絞り込み中は該当を
すべて展開する。シリーズ内の申請数を合計して同時配備数として扱わない。

ITU申請はページ番号付きの `itu(id, {...})` で追加する。国は申請した主管庁
（事業者の国と異なることがある）、日付は受領日、satellitesは申請ページの
「Total number of satellites」。ページに記載のない事業者名を推測で書かない。
sha256・preferredConfiguration・noteはMDBを確認した申請にだけ付ける。

DisplayPublicationのページはBR IFIC公表後も残るが、As Received一覧に出るのは
未公表の間だけ。公表済み申請のページ番号は参照番号（例：USA2023-65539）と
単調に近い関係にあるので、近傍のページの参照番号から探せる。再通告
（Resubmission of Notification）のページにはMDBが付かないため、元の通告や
調整要求のページを選ぶ。整合性（ID・ページ・参照番号・SHA-256の重複、
システムとシリーズの対応、公式URL形式、日付形式、レビュー項目）は
`tests/filingCatalog.test.ts` で検査する。

OPTI-KANSENのレビュー版は構成2を初期選択する。添付NOTE 7によれば、構成1の
Sフラグは今回の費用計算用で、全体の申請からの削除ではない。全構成の機数を
同時配備数として扱わない。OPTI-K-VのNOTE 9は3つの排他的な代替構成を示す。
MDBのorbit_setテーブルに構成3の行がなくても、orbitの構成3を落とさない。

## 仮配置と出典

ユーザーがUTCの基準日時を選ぶ。その日時のGMSTを昇交点の経度に加えてRAANを
構成する。位相を緯度引数と仮定し、近点引数を引いた真近点角から平均近点角に
変換する。欠損位相・経度は等間隔の配置で補う。高度からの半長軸には地球半径
6378.137 kmを使い、周期はアプリの既存伝播モデルで求める。
これは申請の幾何を説明する概念配置であり、ITUの審査モデルの再実装でも
実際の位置・運用状況の再現でもない。

メタデータ dataStatus=filing、filingName、filingConfiguration、filingSource、
filingSha256、申請国＋名称のfilingKeyを選択中の衛星とともにTOMLに保存する。名前文字列から仮配置を判定
しない。3Dでは通常と同じ可視・不可視・選択の色のまま中抜きの円で描き、
実在衛星と形で区別する。画面上部に機数の凡例を出し、選択時にも形を維持する。
構成の切り替えは同じ申請国・名称の申請の衛星だけを置き換え、既存の手動衛星・編隊・他申請を残す。
衛星IDは空いている90000–99999を割り当て、NORAD IDとしては記録しない。

元MDBと未選択の構成はメモリ内のみ。リロード後に切り替えるにはMDBか抽出ファイルを開き直す。
設定ファイルには選択した配置・出典だけが残る。

## 抽出ファイル（.filing.json）

MDBを一度読み込むと「抽出ファイルを保存」で、パーサが読む列だけ
（notice: ntc_id, adm, d_rcv / non_geo: ntc_id, sat_name / orbit: 軌道面の諸元と
orbit_set_id, act_code / phase: 位相角）を端末に保存できる。周波数・ビーム・
アンテナ等のテーブルは含めないため数KB〜数百KBになる。形式は
`format = "constellation-vis/itu-filing-extract"`, `version = 1` に元MDBの
ファイル名とSHA-256を添えたもの（`src/lib/filings/extract.ts`）。

読み込み時は同じ `parseFilingTables` を通すので、範囲チェック・上限・警告・
カタログ照合はMDBと同一になる。ただしJSONは改変できるため、記録されたSHA-256は
元MDBとの一致の証明ではなく、「抽出ファイルから読み込み」と区別して表示する。
抽出ファイルはユーザーの端末にのみ置き、アプリ・リポジトリ・サーバーには
含めない。再配布はITUの利用条件に従う旨をファイル内にも記す。
列を増減する場合は `version` を上げ、旧版の扱いを決めてから変更する。

SpaceX宇宙データセンターはFCC公示への参考リンクとして扱い、完全な配置がない
状態で100万機を生成しない。ITUとの対応・現在の承認状態もこの公示から推定しない。

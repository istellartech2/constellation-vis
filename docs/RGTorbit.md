## 0. 目的（アプリ実装の意図）

本アプリの「RGT条件」ボタンは、ユーザーが **高度 h** と **軌道傾斜角 i** を入力したときに、
RGT 条件を満たす **平均軌道要素（mean elements）** を自動入力するための補助機能である。

ここでの RGT 設計は、まず **J2 摂動のみ** を考えた平均軌道要素で RGT 条件を満たす解を求め、
その後に高次重力場・抗力などで微修正することを前提とする。

---

## 1. RGT の定義（何が「繰り返し」なのか）

RGT (Repeat Ground Track) とは、衛星の **ECEF（地球固定）座標での地上軌跡** が、
ある反復周期 T_rep の後に **同じパターン** に戻る軌道である。

実務では整数比で表し、

- N_S: 反復周期中の衛星公転回数
- N_D: 反復周期中の地球ノーダル日数（Earth nodal period 基準）

として、以下を基本条件とする。

```
N_S * T_S = N_D * T_N
```

ここで、

- T_S: 衛星のノーダル周期（昇交点 -> 次の昇交点）
- T_N: 地球が軌道面（ノード）に対して 1 回転する周期（Earth nodal period）

---

## 2. ECEF で地上軌跡が閉じるための角速度条件

平均要素で見ると、RGT は次の 2 つの位相が同時に整数周回する条件に等しい。

### (A) 衛星のノード基準位相

平均緯度引数（mean argument of latitude）を

```
lambda = omega + M
```

とすると、昇交点から次の昇交点までに 2*pi 増える。
したがってノーダル周期は

```
T_S = 2*pi / (domega_dt + dM_dt)
```

### (B) 地球のノード基準位相

ECEF では、グリニッジ恒星角 theta_G が omega_E で増え、
昇交点赤経 Omega は摂動で dOmega_dt で変化する。
よって「地球（経度）が軌道面に対して進む角速度」は

```
omega_E - dOmega_dt
```

となるため、Earth nodal period は

```
T_N = 2*pi / (omega_E - dOmega_dt)
```

---

## 3. もっとも使われる RGT 条件式（整数比）

RGT は以下の比で表される。

```
tau = N_S / N_D
    = T_N / T_S
    = (dM_dt + domega_dt) / (omega_E - dOmega_dt)
```

平均運動 n に対し、摂動補正を Delta_n とすると

```
dM_dt = n + Delta_n
```

となるため、実務的には

```
tau = (n + Delta_n + domega_dt) / (omega_E - dOmega_dt)
```

という形がよく用いられる。

---

## 4. J2 摂動による代表的な平均変化率

以下は J2 のみを考えた平均（セキュラ）項の代表式。

```
n = sqrt(mu_E / a^3)
```

```
dOmega_dt = - (3 * R_E^2 * J2 * sqrt(mu_E)) / (2 * a^(7/2) * (1 - e^2)^2) * cos(i)

domega_dt =   (3 * R_E^2 * J2 * sqrt(mu_E)) / (4 * a^(7/2) * (1 - e^2)^2) * (4 - 5 * sin(i)^2)

Delta_n   =   (3 * R_E^2 * J2 * sqrt(mu_E)) / (4 * a^(7/2) * (1 - e^2)^(3/2)) * (2 - 3 * sin(i)^2)
```

- mu_E: 地球の重力定数
- R_E: 地球赤道半径
- J2: 第 2 次ゾーナル項
- a, e, i: 平均要素（半長軸・離心率・傾斜角）

---

## 5. RGT 条件を 1 本の方程式にまとめる

与えたい繰り返し比 tau = N_S / N_D を決めると、
未知は主に a（または高度）であり、次の方程式を満たす a を解けば良い。

```
F(a; e, i, tau) = tau * (omega_E - dOmega_dt(a,e,i))
                 - (n(a) + Delta_n(a,e,i) + domega_dt(a,e,i))
               = 0
```

この式に 4 章の J2 近似式を代入し、数値的に a を求める。

---

## 6. アプリ実装向けの設計フロー（高度と傾斜角から RGT を作る）

「RGT条件」ボタンでは、ユーザー入力 (h, i) から **RGT 近似軌道** を生成する。
J2 近似を使った実装フローを以下にまとめる。

### 手順

1. 入力: 高度 h, 傾斜角 i（必要なら e の既定値を 0 にする）
2. 初期半長軸: a0 = R_E + h
3. a0 で dOmega_dt, domega_dt, Delta_n を計算し、
   tau0 = (n + Delta_n + domega_dt) / (omega_E - dOmega_dt) を求める
4. tau0 に最も近い整数比 N_S / N_D を選ぶ
   - 例: N_D, N_S を小さな範囲で探索し、|tau0 - N_S/N_D| を最小化
   - 反復周期が長すぎる組は避け、扱いやすい周期に制限する
5. tau = N_S / N_D を固定し、F(a; e, i, tau)=0 を数値的に解く
   - 初期値は a0
   - 2 分法 / ニュートン法 / secant 法などの root finding を使用
6. 得られた a を高度に戻し、
   - a, e, i を平均要素として入力欄に反映
   - Omega, omega, M は RGT 条件に影響しないため、
     既定値やユーザー指定値をそのまま使ってよい

### 擬似コード例

```python
# 入力: h, i, e=0, 探索上限 ND_max, NS_max
mu_E = 3.986004418e14
R_E = 6378137.0
J2  = 1.08263e-3
omega_E = 7.2921150e-5  # rad/s (恒星日ベース)

a0 = R_E + h

# J2 近似で tau0 を計算
rates = j2_rates(a0, e, i)
ns = sqrt(mu_E / a0**3)

# tau0 = (n + Delta_n + domega_dt) / (omega_E - dOmega_dt)
# -> 最小誤差の N_S/N_D を探索
N_S, N_D = pick_ratio(tau0, NS_max, ND_max)

tau = N_S / N_D

# F(a)=0 を解く
solve_a = root_find(lambda a: F(a, e, i, tau), a0)

# 結果: mean elements (a, e, i)
```

## 6.1 整数比の探索ルール（推奨パラメータ）

RGT 条件ボタンは、ユーザー入力 (h, i) から **最初の近似解** を提示することが目的である。
そのため、探索する整数比の範囲を **適度に制限** し、
「過剰に長い反復周期」や「極端に大きな N_S」を避ける。

推奨する探索範囲（実装の初期値）:

```
N_D (repeat days) : 1 ～ 30
N_S (repeat orbits): 1 ～ 2000
```

この範囲なら、LEO〜MEOの一般的な軌道で十分に近い比が得られ、
反復周期が長すぎる設計を回避しやすい。

評価は以下の誤差を最小化する単純ルールでよい:

```
error = |tau0 - N_S/N_D|
```

さらに、得られた比は最大公約数で簡約し、
同じ比なら **N_D が短い方（反復周期が短い方）** を優先する。

---

## 6.2 数値解の探索範囲（高度の制約）

F(a)=0 の根は数値的に探索するが、
アプリ用途では **高度の探索範囲** を設けておくと安定する。

推奨する初期制約:

```
高度 h: 120 km ～ 50,000 km
```

この範囲を超える場合は「解なし」として扱い、
入力値の見直しを促すのが実務的。

---

## 6.3 パラメータの組み合わせ（UI の2モード）

RGT 条件は **1本の方程式** なので、次の 2 モードが実用的である。

```
1) 傾斜角 i + RGT比 (N_S/N_D) -> 高度 h を解く
2) 高度 h + RGT比 (N_S/N_D) -> 傾斜角 i を解く
```

いずれも離心率 e は固定（通常 e=0）として扱う。

---

## 7. なぜ J2 から始めるのか（設計方針の整理）

J2 のみで得るのは「一次近似の nominal RGT」である。
完全な RGT（回転座標系での厳密周期解）は、
高次重力場や共鳴・リブレーションの影響も含む。

実務では以下の順序が典型的：

1. J2 の平均要素で RGT 条件を満たす a を求める
2. 高次重力場・抗力を含めた高忠実度モデルで軌道を微修正
3. 長期で地上軌跡が閉じるよう調整する

アプリ実装では、まず 1 を確実に実装し、
必要に応じて 2, 3 を拡張する。
